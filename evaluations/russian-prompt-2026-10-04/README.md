# Корпус и результаты проверки русской редакторской инструкции

Приоритет: естественный русский, точность и умеренные правки. [Отчёт](../../docs/PROMPT_EVALUATION_2026-10-04.md) объясняет выбор инструкции и ограничения результатов. Это слепые оценки ИИ-проверяющих на синтетических текстах; оценка людьми не проводилась.

- `corpus.json`, `rubric.md`, `protocol.json` — зафиксированные тексты, критерии и план.
- `candidates/` — шесть системных инструкций; `selected.txt` — выбранный `precise`.
- `selection.json` — решение до отложенных прогонов; его digest сводки относится к неизменной `development-summary.json`.
- `attempts.jsonl` — все экспериментальные попытки, включая ошибки и 12 исключённых прогонов с неправильно переданным образцом стиля. Поле `excluded` отмечает только ошибку инструмента; защищённые/смысловые неудачи из статистики не исключаются.
- `systems/` — точные системные сообщения по SHA-256; `calls[].request.user_content` — фактически отправленные данные. `output` — доставленный результат, `raw_first_output` — первый ответ до вычитки/проверки. Если попытка отклонена, доставленного результата нет.
- `development-summary.json`, `heldout-one-pass-summary.json`, `heldout-two-pass-summary.json` — оценки, анонимные метки, разногласия и соответствие попыткам. `primary` и `secondary` сохраняются отдельно; отсутствующая или неопределённая оценка не считается принятием.
- `manifest.json` — SHA файлов, digest моделей, версия runtime и параметры генерации; `user-templates.json` — точные пользовательские сообщения для повторения.
- `frozen-selftest.json` — офлайн-проверка готового EXE и SHA встроенного промпта; качество модели ею не измеряется.

Журналы содержат синтетические тексты и обычные ответы моделей. Отдельное поле `message.thinking` не экспортировано. В старых записях поле `date` обозначает дату начала исследования; новые записи имеют фактический `started_at` с часовым поясом +05:00. Скорость — наблюдение этого компьютера, включая возможную загрузку модели, а не изолированный тест производительности.

## Повторить генерацию

Нужны Python 3.11+ и установленный через GUI локальный runtime с выбранной моделью. Запускайте из корня проекта. Завершите другую обработку локальным ИИ, чтобы модели не конкурировали за память.

```powershell
python tools/evaluate_prompt_study.py --model "qwen3.5:4b" --variant selected --case H1 --seed 42 --output local-evaluation/replay-selected-4b-H1-42.jsonl
```

`--variant baseline` повторяет исходный промпт; `--second-pass` включает вычитку. Без `--case` запускаются все 14 текстов; параметр можно повторять. Каждый новый запуск записывайте в новый файл: инструмент отказывается перезаписывать результаты.

Повторный инструмент берёт системную инструкцию и пользовательские сообщения из проверяемых файлов, независимо от текущего `prompts.messages`. Для четырёх изученных моделей он проверяет digest весов, версию runtime и параметры перед генерацией. Для расширения исследования на другую установленную модель обязательные pin отсутствуют, но фактические метаданные записываются. Seed можно менять; идентичность ответов на другом runtime/драйвере/оборудовании не гарантируется.

Системные сообщения сохранены в UTF-8 с точными переносами LF из запросов. Локальный `.gitattributes` отключает преобразование переносов в файлах, чьи байты проверяются по SHA-256.

Для оценки новых результатов используйте `rubric.md`, сравнивая каждый ответ с исходником. Инструмент повторяет генерацию и механические проверки, но не заменяет редакторскую проверку смысла.
