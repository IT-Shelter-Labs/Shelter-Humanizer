# Архитектура

Python 3.11+, стандартная библиотека; Tkinter/ttk для GUI. Никакого backend. В одном пакете — модели данных, защита участков, Unicode-проверка, русские правила, промпт, клиент модели, общий сервис. GUI и CLI вызывают одинаковые функции.

Deterministic: позиции символов и подсказок, ограниченная очистка, правила, diff, сравнение защищённых данных, применение ограниченных исправлений, JSON-отчёт, ограничение размера и протокол API. Модель: смысловая переработка и предложения для вычитки.

Сетевой слой: HTTPS для внешнего API; HTTP допустим только для loopback Ollama/совместимого локального сервера. Никаких редиректов с ключом, неявных retries или смены провайдера. Пределы размера ответа/ввода и таймаут. Ключ не помещается в промпт, файлы настроек, ошибки или отчёты; остаётся в памяти текущего запуска.

GUI запускает сеть в worker thread. Tk изменяет только главный поток через очередь. Отмена отменяет принятие результата и следующий проход; незавершённый HTTP-запрос может ждать таймаута. Новый запуск и редактирование исходника не позволяют старому ответу заменить новый результат.

Защита данных: модель получает читаемый исходник и список сохраняемых фрагментов (до 128 уникальных значений). После ответа `validate_protected` сравнивает multiset всех распознанных чисел и защищённых участков: код, ссылки, цитаты, числа с единицами, явные термины. Изменение/потеря/дублирование или добавление защищённого участка отклоняет результат. Проверка полная для распознанных участков, даже если список в задании ограничен. Это буквальная проверка, не доказательство смысла. Термины чувствительны к исходному написанию; изменение падежа может вызвать отказ.

Обычный URL отделяется от конечной пунктуации и лишней закрывающей скобки; сбалансированные скобки сохраняются. Markdown-ссылка защищается целиком, включая особую конечную пунктуацию в адресе. Такое разграничение нужно, чтобы точка предложения не считалась изменением адреса.

Глубокая редактура получает до 24 конкретных рекомендаций из `editorial_targets`. Эти правила также видны пользователю как предложения, но не удаляют содержательные подводки автоматически. Почти неизменённый длинный ответ с такими местами отмечается через пересечение четырёхсловных фрагментов; это линейная проверка повторения, не оценка авторства.

Второй проход в `proofread.py` получает справочный исходник, замечания по оговоркам и предложения черновика с локальными ID. Возвращает JSON edits: ID и replacement. Приложение отклоняет неизвестные/повторные ID, лишние поля, более 12 исправлений, пустые/длинные замены и добавление абзаца в обычное предложение. Общий объём замен ограничен 40% черновика (для короткого — минимум 120 символов). JSON применяется целиком, затем повторно проверяются защищённые данные. Неверный формат/объём, новые категории смысловых замечаний, увеличение расхождений в оговорках или числа шаблонных подводок сохраняют первую проверенную редактуру с явным предупреждением. Изменённые защищённые данные отклоняют результат. Эта проверка не обнаруживает все смысловые/языковые ухудшения. Сетевые ошибки и отмена сохраняют прежний результат. Новых запросов или смены модели при ошибке нет.

Unicode: сохраняем русские буквы, кавычки, тире, ударения и валидные emoji joiners. Подозрительные соединители в русском слове отличаются от связок в эмодзи и других письменностях. В GUI по умолчанию включены замена специальных пробелов и NFC; омоглифы выключены. Защищённые участки не чистим автоматически. CLI включает дополнительные замены только по флагам. ИИ-результат чистим после проверки; локальные маски защищают участки только во время очистки и не отправляются модели. Исходник не меняем.

Сборка EXE происходит на Windows. Linux исходники используют тот же пакет; GUI проверяется с настоящим Tk, в CI через Xvfb. Кросс-платформенная декларация не заменяет фактическую проверку.

Интерфейс: общие палитры `appearance.py`, привязки клавиш и подсказки `ui_helpers.py`.
На Windows сочетания редактирования определяются по виртуальному коду клавиши,
на других системах — по английским/русским keysym. Обработка идёт перед стандартным
bindtag виджета, поэтому вставка не дублируется. На Windows bit 8 — NumLock, а Alt —
0x20000; эти модификаторы не смешиваются. Text и Entry редактируются напрямую,
без зависимости от перевода виртуальных событий Tk. Подсказки появляются при наведении,
привязаны к своему окну и скрываются при смене фокуса/сворачивании/прокрутке.
В 0.1.3 постоянной боковой панели нет; параметры доступны в отдельных диалогах.

Мастер `local_setup.py` использует отдельную очередь с данными, без Tk-объектов в worker.
`local_models.py` запускает только явно подтверждённый pull одной из четырёх моделей
на loopback Ollama. Поток NDJSON ограничен по размеру строки/общего статуса;
чтение частями позволяет проверять отмену до конца строки. Готовность принимается
только после `status: success`. Внешние адреса, редиректы и произвольные имена моделей
в мастере отклоняются. Приватные тексты в процессе загрузки не используются.

`managed_runtime.py` устанавливает собственную переносимую Ollama на Windows x64:
[официальный формат для встраивания](https://docs.ollama.com/windows#standalone-cli).
Версия 0.35.1, размер и SHA256 закреплены в коде; никакого выполнения shell-скриптов
или получения «latest» при запуске. HTTPS-редиректы разрешены только на домены выдачи
GitHub. Частичная загрузка продолжается через проверенный Range; архив принимается
только после проверки размера и SHA256. Распаковка отклоняет traversal, symlinks,
потоки NTFS и дубли путей; проверяет свободное место. OS file lock запрещает
две одновременные установки, staging и rename делают замену транзакционной.
Испорченная прежняя папка сохраняется отдельно. Установленные exe сверяются с receipt.

Данные лежат в `%LOCALAPPDATA%\ShelterHumanizer\ai`: runtime, модели, имя выбранной
модели. Ключи и тексты здесь не сохраняются. Только подтверждение в мастере запускает
загрузку; на повторном запуске GUI автоматически подключает выбранную в мастере модель.
Само открытие приложения не вызывает загрузку новых файлов.
Ollama слушает отдельный loopback-порт, получает свой `OLLAMA_MODELS`, отключённое
облако и лимит одного загруженного runner. На Windows собственный процесс включён в
Job Object с KILL_ON_JOB_CLOSE: закрытие приложения или аварийное завершение убивает
этот процесс и потомков. Не ищем/не завершаем процессы сторонних установок.
`runtime.close()` также отменяет незавершённый запуск. На Linux мастер установки
не поддерживается: используется вручную настроенный сервер.

Проверки: безопасные архивы/хеши/Range/отмена, блокировка установки, реальное завершение
дочернего дерева с сохранением постороннего процесса. Отдельный Windows acceptance
`tools/native_keyboard_smoke.py` отправляет реальные клавиши только своему окну,
проверяя PID foreground; переключает английскую/русскую раскладку и восстанавливает её.


Интерфейс 0.1.3 применяет progressive disclosure: главный экран содержит два поля
и одну акцентную кнопку; настройки обработки/текста и проверки — отдельные окна.
Перенос параметров не меняет сервис и CLI. UI-названия типов правок в EDIT_CHOICES
отдельны от ключей edit/rephrase и метаданных промпта. Стиль хранится в прежнем поле
voice, но интерфейс использует «Стиль и важные слова». В GUI 0.1.4 по умолчанию
глубокая переработка и два прохода; второй можно отключить.

Окно ИИ-чата копирует задание и вставляет ответ только по явному нажатию. Текст не
отправляется браузером автоматически. Перед вставкой проверяется наличие исходника,
совпадение с исходником скопированного задания и отличие от самого задания.
Manual compare показывает изменения фактов; строгая проверка protected atoms здесь не действует.
Окно проверок не блокирует главное; предупреждения о смысле показываются автоматически.
`auto_connect=False` отключает запуск сохранённого ИИ в диагностике EXE и GUI-тестах.

В 1.0.0 основной пресет — DeepSeek R1 0528 Qwen3 8B. Его рассуждения отделены от
итогового текста; параметры и ограничения перечислены в MODELS_AND_PROMPT.md.
После финальной очистки встроенного ИИ-ответа защищённые данные проверяются повторно.

Буфер обмена Windows использует CF_UNICODETEXT через отдельный clipboard.py.
Это избегает искажения длинного русского текста при преобразовании Tk STRING.
UTF-16 данные ограничены по размеру; NUL при копировании отклоняется явно,
занятый clipboard ожидается не более 50 мс. На других системах используется Tk.
