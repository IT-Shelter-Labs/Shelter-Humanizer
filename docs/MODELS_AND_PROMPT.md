# Модели и редакторская инструкция · 1.0.0

## Выбор модели

Основной пресет — [DeepSeek-R1-0528-Qwen3-8B, Q4_K_M](https://ollama.com/library/deepseek-r1:8b-0528-qwen3-q4_K_M),
около 5,2 ГБ. Это выпуск мая 2025 года на базе Qwen3 8B, не новейшая полная серия
DeepSeek. Выбран как основной вариант после положительной ручной оценки при
подготовке выпуска. Это не сравнительный benchmark всех моделей и жанров.
[Официальная карточка](https://huggingface.co/deepseek-ai/DeepSeek-R1-0528-Qwen3-8B)
описывает происхождение и лицензию MIT.

Альтернативы: [Qwen 3.5 4B](https://ollama.com/library/qwen3.5:4b) (≈3,4 ГБ),
[Qwen 3 1.7B](https://ollama.com/library/qwen3:1.7b) (≈1,4 ГБ) и
[Qwen 3.5 9B](https://ollama.com/library/qwen3.5:9b) (≈6,6 ГБ).
Модели Qwen 2.5 не предлагаются. RAM в интерфейсе — ориентир, не измеренный минимум.

## Протокол генерации

- DeepSeek R1: `think=true`, `temperature=0.6`, `top_p=0.95`, `top_k=0`,
  `min_p=0`, `repeat_penalty=1`, `num_ctx=32768`, `num_predict=16384`.
- Qwen 3/3.5: `think=false`, `temperature=0.7`, `top_p=0.8`, `top_k=20`,
  `min_p=0`, `repeat_penalty=1`, `num_ctx=16384`, `num_predict=8192`.
  Для Qwen 3.5 также `presence_penalty=1.5`.
- Внешний совместимый API получает обычные параметры chat completions без
  специфичных переключателей Ollama. Каждый сервис имеет свои ограничения.

R1-0528 поддерживает system-инструкции. Ollama отделяет рассуждения в
`message.thinking`; приложение использует только `message.content`.
[Документация thinking](https://docs.ollama.com/capabilities/thinking).
Ответ только с рассуждениями или прерванная генерация не принимаются.
Рассуждения могут занять большую часть лимита; на CPU возможен таймаут.
Во встроенном локальном подключении лимит запроса остаётся 180 секунд.

## Редакторская основа

В рабочей версии после проверки 4–5 октября 2026 года используется короткая
инструкция, выбранная по результатам прогонов на четырёх локальных моделях.
[Точный системный промпт](../evaluations/russian-prompt-2026-10-04/selected.txt)
совпадает с `SYSTEM` в приложении. [Отчёт](PROMPT_EVALUATION_2026-10-04.md)
разделяет один проход и полный путь со второй вычиткой.

По умолчанию GUI выбирает небольшие правки: сохранить содержание, голос автора,
порядок подачи и абзацы; исправить грамматику и тяжёлые формулировки. Хороший текст
может остаться без изменений. Отдельно сохраняются участники и их действия,
условия, атрибуции, отрицания, ограничения и приблизительность величин.
Образец стиля задаёт только манеру письма, его факты не переносятся в результат.

В режиме «Переформулировать» можно перестроить фразы и абзацы по содержанию,
сохраняя хронологию и логику. Сравнительные результаты этого исследования
относятся к небольшим правкам; качество глубокой переработки отдельно не оценено.

Жанр, глубина, образец стиля, важные слова и исходник передаются как JSON-данные.
Команды внутри исходника не являются инструкциями. Это снижает неоднозначность,
но не превращает языковую модель в надёжную границу безопасности.

## Проверка и очистка

Сначала проверяются числа и защищённые фрагменты. Вторая вычитка предлагает
ограниченные замены по ID предложений; формат, объём, буквальная сохранность
и распознанные смысловые изменения проверяются локально. Неприемлемая вычитка
сохраняет первый вариант с предупреждением; изменение защищённых данных
отклоняет ответ.

**Очистка выполняется после обоих проходов**, затем результат анализируется и
сравнивается с исходником. После очистки сохранность защищённых данных проверяется
ещё раз. Цитаты, ссылки, код, числа и явные термины не меняются очисткой.
При вставке ответа из внешнего чата тоже выполняется очистка, но строгая проверка
всех защищённых фрагментов встроенного ИИ-режима к ручному переносу не относится.

Спецпробелы и NFC включены в GUI; похожие латинские буквы — отдельный выбор.
UTF-8 и Unicode не являются «следом ИИ». Нормальные буквы и emoji сохраняются.
