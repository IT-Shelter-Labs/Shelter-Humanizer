# Shelter Humanizer 1.1.1rc1

Локальная проверочная сборка. Опубликованный 1.1.0 не заменяется этим архивом автоматически.

- ПКМ и Shift+F10 открывают меню редактирования в исходнике, результате и полях настроек.
  Доступны копирование, вставка, вырезание, удаление выделенного и выделение всего;
  в многострочном редакторе также отмена и повтор. Выделение при открытии не теряется.
  Недоступные операции выключены, поля только для чтения не изменяются.
- HTTP 500 больше не интерпретируется как подтверждение нехватки памяти. Локальный
  JSON-ответ движка разбирается с пределом 8 КиБ, после чего сырой текст отбрасывается.
  Для распознанных ошибок RAM/VRAM, GPU, файла, архитектуры или процесса показываются
  фиксированные подсказки. Для неизвестной причины приложение прямо сообщает, что она неизвестна.
- Ошибки в середине NDJSON-потока тоже распознаются; частичный ответ не принимается.
- В подключении Ollama появился опциональный режим «Только процессор» (`num_gpu=0`).
  Настройка действует в текущем запуске, может работать медленнее и не решает нехватку RAM.
  Она не меняет модель, системные переменные или API-провайдера. Повторный запрос ручной.
- Диагностика сохраняет последнюю ошибку генерации после проверки подключения.
  Добавлены безопасная категория ошибки, HTTP-статус, CPU-only и версия встроенной Ollama.
  Сырой ответ, исходник, ключи и пути в неё не включаются.
- При изменении CPU-only в подключении сохраняется управление собственным процессом
  Ollama и прежний предел времени генерации. Режим устройства входит в проверку продолжения частей.

Причина сбоя на компьютере подписчика не установлена: точная модель, воспроизводимый
пример и диагностика от него не получены. Проверки на его GPU и реальное ускорение
CPU/GPU не проводились. Новая обработка не обещает устранения всех HTTP 500.
Промпт, Qwen 3.5 4B по умолчанию, защита данных и Unicode-очистка сохранены.

## English

Local test build with right-click editing menus, safe local-engine error categories,
optional per-request CPU-only Ollama execution and preserved last-failure diagnostics.
Unknown HTTP 500 causes remain explicitly unknown. No automatic retry, model switch,
driver change or raw-error export. The subscriber's hardware failure has not been reproduced.
