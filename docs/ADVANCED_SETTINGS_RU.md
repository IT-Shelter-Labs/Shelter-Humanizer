# Дополнительные возможности 1.1

Это инструкция к версии 1.1.0. Главный сценарий прежний:
вставить текст, нажать «Улучшить текст», прочитать и скопировать результат.
Qwen 3.5 4B и редакторская инструкция IT Shelter остаются предустановками.
Сохранённый явный выбор модели не заменяется.

## Своя модель

Откройте «Настройки текста» → «Расширенные» → «Свои модели и установка…».
В мастере есть вкладка своих моделей и три варианта:

1. **Каталог Ollama.** Откройте официальный каталог, скопируйте точное имя с тегом
   (например `qwen3.5:4b`), вставьте в поле и подтвердите загрузку. Вводить команды
   или ссылки не нужно. Модель скачивается во встроенную переносимую Ollama.
2. **Уже установленная модель.** Кнопка «Модели встроенной Ollama» показывает модели
   именно этой копии движка. Выберите имя и подключите его без повторной загрузки.
3. **Файл GGUF.** Выберите один совместимый `.gguf` и задайте ему локальное имя.
   Приложение проверит заголовок и хеш, передаст файл локальному движку и создаст
   модель. Исходный файл не меняется. Уже занятое имя не перезаписывается.

GGUF не гарантирует совместимость: архитектуру и шаблон диалога должна поддерживать
встроенная версия Ollama. Разделённые GGUF, LoRA, vision-проекторы и модели,
требующие исполнения своего Python-кода, этот мастер не импортирует.
Выбирайте текстовую instruct/chat-модель из доверенного источника, проверьте её
лицензию и требования к памяти. Облачные теги в локальном мастере не принимаются.
При импорте нужна дополнительная копия файла и свободное место с запасом.

Если у вас **своя Ollama или LM Studio**, используйте «Выбрать ИИ» → «Настроить
подключение». Список там относится к указанному серверу. Для Ollama выберите
«ИИ на компьютере» и его адрес, для OpenAI-совместимого сервера LM Studio или
другого поставщика выберите «ИИ-сервис по ключу». Укажите точное имя модели.
Свой сервер приложение не устанавливает и не выключает.

Загрузка и импорт начинаются только после подтверждения. Произвольные модели
могут работать медленнее или хуже предустановок. Первое испытание делайте на
коротком несекретном тексте; установка модели не подтверждает качество редактуры.

## Своя инструкция (промпт)

«Настройки текста» → «Расширенные» → «Своя редакторская инструкция…».
Отредактируйте инструкцию и нажмите «Применить». Она действует на первый проход
редактуры и на задание для внешнего ИИ-чата. Протокол дополнительной вычитки
остаётся отдельным, чтобы приложение могло проверять небольшие исправления.

Без галочки сохранения инструкция действует до закрытия приложения. С галочкой
она сохраняется обычным текстом в
`%LOCALAPPDATA%\ShelterHumanizer\editor-preferences.json`.
Не помещайте в неё ключи, пароли или личные данные. При работе через API инструкция,
исходник и образец стиля отправляются выбранному сервису.

«Вернуть предустановку» и затем «Применить» восстанавливают инструкцию IT Shelter
и удаляют сохранённую пользовательскую инструкцию. Снятие галочки также удаляет
прежнее сохранение. Пустая инструкция не принимается, предел 12 000 символов.

Своя инструкция не отключает программную проверку чисел, цитат, ссылок, кода и
важных слов. Очистка скрытых знаков выполняется после ИИ. Проверки не доказывают
полную смысловую эквивалентность, поэтому результат нужно прочитать.

## Длинные документы

В «Расширенных» включите «Длинный текст: обрабатывать частями с подтверждением».
Перед обработкой приложение покажет количество частей. Части идут по порядку;
цитаты, ссылки и код не разрезаются. Приложение не пропускает части молча.
Вторая вычитка увеличивает количество запросов, при API это может увеличить цену.

После сбоя успешные части остаются **только в памяти**, пока окно открыто. Повторное
«Улучшить текст» с тем же исходником, моделью и параметрами продолжит работу.
Смена настроек или исходника начинает обработку заново. До завершения всех частей
старый результат не заменяется. При закрытии приложения прогресс теряется.
Части редактируются отдельно, поэтому проверьте связность документа после сборки.
CLI `--chunks` обрабатывает части за один запуск, без сохранения продолжения.

## Подключение и диагностика

В проверочной 1.1.1rc1 в «Выбрать ИИ → Настроить подключение» для Ollama есть
**«Только процессор · при сбоях видеокарты»**. Приложение передаёт `num_gpu=0`
в запросе к выбранной Ollama. Эта опция может помочь при ошибке GPU/драйвера,
но не гарантирует исправление сбоя и не устраняет нехватку оперативной памяти.
Работа может быть значительно медленнее. Это настройка текущего сеанса;
режим на видеокарте восстанавливается снятием галочки, запрос повторяют вручную.
Для API эта настройка не передаётся. Управление собственным процессом сохраняется.

«Настройки текста» → «Расширенные» → «Диагностика и проверка ИИ…».
Проверка подключения получает список моделей и сведения сервера без генерации.
Диагностическая сводка содержит версию и идентификатор сборки, ОС, доступную память,
имя модели, код ошибки и числовые показатели запроса. Текст, промпт, ключ, адрес
сервера и личные пути в неё не добавляются. Просмотрите сводку перед отправкой.

Полный «Отчёт JSON» в окне проверок содержит оба текста и предназначен для другого
сценария. Не путайте его с диагностикой.

В 1.1.1rc1 поле `last_failure` сохраняет последнюю ошибку обработки до закрытия
приложения, даже если затем проверка подключения прошла успешно. Оно может относиться
к предыдущей модели; имя и CPU-only указаны внутри самой записи.
Категория движка определяется по нескольким известным фразам, не доказывает причину
на уровне оборудования и никогда не содержит исходный текст сообщения сервера.

Контекст локальной модели подбирается по приблизительному размеру задания с запасом
на ответ. Это оценка, а не точный токенизатор. Если задания слишком много, приложение
предложит части вместо скрытого обрезания. Настройка отключается в подключении.
Для несовместимого API можно выключить потоковый режим в настройках подключения.

## Сохранность и ограничения

- Ручные правки результата, сделанные во время ожидания ИИ, не заменяются без выбора.
- При выходе предлагается сохранить несохранённый текст в TXT; отмена оставляет окно.
- TXT с BOM читается как UTF-8/16/32; старую кодировку Windows-1251 выбирают по превью.
- Предупреждения о сильном сокращении, потере списка и смене алфавита приблизительны.
  Это поводы для проверки, а не определение авторства текста.
- На Windows второй запуск GUI не создаёт ещё одну копию. На Linux этот механизм
  не реализован; Linux-бинарник в этом выпуске не собирался.
- Приложение не подписано сертификатом. Защиту Windows отключать не требуется.
- Протокол импорта GGUF проверяется локальным тестовым сервером. Проверка всех
  реальных GGUF, устройств и API-поставщиков не проводилась.
