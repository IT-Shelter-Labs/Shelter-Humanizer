# Безопасность и данные

Без настройки приложение не делает сетевых запросов. История и ключи не записываются
автоматически; мастер сохраняет только имя выбранной модели. В режиме API/Ollama исходник
целиком, включая цитаты, числа, ссылки, код, важные слова и образец стиля, отправляется
указанному серверу. Защищённые данные читаемы для модели; проверка их сохранности
происходит локально после ответа. Это защита от изменений, а не сокрытие данных от сервиса.
API-ключ находится в памяти процесса; отчёт JSON включает оба текста, но не ключ.

Внешним сервисам разрешён HTTPS, HTTP — только loopback. Перенаправления не выполняются,
чтобы не передать Authorization другому адресу. Ошибки сервиса показываются без тела
ответа и ключа. Нет скрытых повторов и переключения провайдеров. Отмена не прерывает
уже отправленный HTTP-запрос; его результат не применяется, новые проходы не запускаются.

После явного подтверждения Windows-мастер скачивает закреплённую переносимую Ollama
с GitHub. Только для этой загрузки разрешены HTTPS-редиректы на домены выдачи GitHub,
без API-ключа. Размер и SHA256 проверяются до распаковки и запуска. Автозапуск и службы
не добавляются. Модели, профиль runtime и выбор модели хранятся в отдельной папке
данных Shelter Humanizer. Собственный сервер слушает только loopback, облако отключено;
его дерево процессов завершается при закрытии приложения. Сторонние процессы Ollama
не завершаются. При обычном открытии приложения загрузка не начинается.

Не помещайте ключи и личные тексты в issues, скриншоты, отчёты о багах или коммиты.
Содержимое редактируемого текста и образца стиля считается данными, а не инструкциями;
языковая модель всё же не является надёжной границей безопасности.

Для публичного репозитория включите GitHub Private vulnerability reporting до публикации.
После включения сообщение об уязвимости отправляется через Security → Report a vulnerability.
До появления такого канала не публикуйте секреты или работающий exploit в открытом issue.
